# Testing Documentation

This document describes the various testing strategies and scenarios for the `grants-reporting-collector` service.

## Unit Testing

Unit tests are written using [Vitest](https://vitest.dev/).

To run all unit tests:

```bash
npm run test
```

To run tests with coverage:

```bash
npm test
```

## End-to-End Idempotency Testing

We have an automated scenario to verify that the application correctly handles duplicate messages received via SQS.

### Prerequisites

- [AWS CLI](https://aws.amazon.com/cli/) installed on your host machine.
- [Docker](https://www.docker.com/) and [Docker Compose](https://docs.docker.com/compose/) installed and running.
- The project's local environment running via Docker Compose:
  ```bash
  docker compose up --build -d
  ```

_Note: The script automatically loads AWS credentials from `compose/aws.env` to interact with local services._

### Running the Idempotency Test

A Bash script is provided to automate the injection of messages and verification of side effects (MongoDB, S3, and Logs).

```bash
./scripts/test-idempotency.sh
```

### What the test does:

1.  **Environment Setup**: Clears the `processed_messages` collection in the local MongoDB container.
2.  **First Message Injection**: Sends a valid reporting event to the local SQS queue with a unique `messageId`.
3.  **Verification**:
    - Checks that a file is created in the S3 bucket (`raw-event-bucket/reporting-events/`).
    - Verifies that the logs show "Received New Reporting event".
4.  **Second Message Injection**: Sends the **same** `messageId` again.
5.  **Verification**:
    - Confirms that **no new file** is added to S3.
    - Verifies that the logs show:
      - `Receipt of a duplicate message: <messageId>`
      - `Event tracked` with `event: "duplicate-message"`

### Troubleshooting

If the test fails, check the following:

- Ensure all containers are healthy (`docker compose ps`).
- Verify the container names in `scripts/test-idempotency.sh` match your local environment (the script uses default names generated by Docker Compose).
- Check the floci dashboard or logs if SQS/S3 interaction fails.
